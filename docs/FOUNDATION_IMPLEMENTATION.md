## 이번 단계의 범위

로그인/로그아웃, Role·조직·사업 Context, 프로그램 기반 Navigation, 공통 UI와 mock 데이터 구조를 구현했다. 세부 농할·POS HUB·정산·회비·공개·CMS 업무는 준비 화면으로 연결한다. 기존 구현계획 문서는 전체 제품의 목표이며 이 문서는 이번 단계의 실제 구현 범위를 기록한다.

실행 파일: `dist/adms-demo.html`. 해당 파일 하나를 Windows Edge/Chrome으로 직접 열 수 있다. `file://` 실행 시 서버·Node.js·인터넷·별도 자산 설치가 필요 없다.

## 로그인 계정

| ID | 비밀번호 | Role | 조직 | 홈 |
|---|---|---|---|---|
| admin | 1234 | 시스템 관리자 | ADMS 플랫폼 운영 | 시스템 관리자 홈 |
| at | 1234 | AT / 관리감독기관 | aT | 관리감독기관 홈 |
| assn | 1234 | 협회 / 운영기관 | 한국마트협회 | 운영기관 홈 |
| mart | 1234 | 마트 대표 관리자 | 한빛유통(주) | 마트 홈 |

- 틀린 ID/PW는 같은 로그인 실패 안내를 표시한다. 데모 계정 버튼은 입력란만 채우며 로그인은 제출 버튼으로 실행한다.
- 로그인 성공 시 계정 마스터에서 Role/조직을 계산하고 첫 번째 허용 사업과 `/home`으로 이동한다.
- localStorage에 `accountId`, `businessId`만 저장한다. PW/Role/조직을 저장하지 않는다. 복구 시 계정 정상 여부와 허용 사업을 검증한다.
- 저장소 읽기/쓰기/삭제 오류는 잡아서 메모리 세션으로 계속 동작한다. 저장소 차단 상태에서는 새로고침 시 재로그인이 필요하다.
- 로그아웃은 메모리와 저장 세션을 지우고 로그인 화면으로 이동한다. 뒤로가기나 보호 경로 직접 접근으로 재진입할 수 없다.
- 이 구조는 공개 자격정보를 쓰는 **Mock 인증**이다. 브라우저 세션 저장이나 프런트엔드 가드를 실제 운영 인증/보안 경계로 간주하지 않는다.
- 지회·마트 부관리자·마트 일반 관리자 Role은 모델과 권한 데이터에 포함한다. 추가 로그인 계정은 만들지 않았다.

## 계정별 노출 메뉴

모든 계정에 홈을 제공한다. **농할 운영은 농할 사업, 알뜰소비 메뉴는 알뜰소비 사업을 선택했을 때** 노출한다. 조직 공통 메뉴와 사업 참여 안내는 사업 전환 후에도 유지된다.

### admin

- 조직·계정 관리: 조직 관리, 관리자 계정 관리, 권한 관리.
- 사업 관리: 사업 마스터, 참여 조직·역할, 사업-프로그램 매핑.
- 프로그램 관리: 메뉴/프로그램 관리, 사용·중지.
- POS 연동 HUB: POS 마스터, Capability, 데이터소스·인터페이스, 표준 스키마, 필드·코드 매핑, 점포 POS 연동, 연동 현황·이력.
- 외부 연동: AT, 알뜰소비플랫폼, 금융, 기타 연동.
- 시스템 운영: Excel 양식, 자동 작업 현황, 알림 관리, 공통코드, 감사·변경 이력.

시스템 관리자는 모든 프로그램의 조회 권한을 갖는다. 기본 Sidebar는 PRD 시스템 관리자 IA를 사용한다. `메뉴/프로그램 관리`의 전체 목록은 사업 변경과 무관하게 유지하고, 다른 Role의 업무 프로그램으로 이동할 때만 선택 사업의 연결 여부를 검사한다. 이것은 다른 사용자의 신분으로 로그인하는 기능이 아니다.

### at

- 농할 운영: 주차별 계획 관리, 운영 현황.
- 정산 관리: 청구 내역 관리, 불인정·재심사, 최종 정산.
- 알뜰소비플랫폼: 참여 현황, 공개 데이터, 전단 게시, 연동 현황·이력.
- 공통: 종합 통계.

협회 내부 이상 감지와 협회→마트 지급 실행은 노출하지 않는다. 알뜰소비는 조회 범위다.

### assn

- 회원·조직 관리: 가입·참여 심사, 회원사 관리, 운영자 계정 현황, 지회 관리, 회비·수납.
- 농할 운영: 예산 관리, 주차별 계획, 행사상품 등록현황, 집행 실적, 이상 감지.
- 농할 정산: 정산 청구, 불인정·재심사, 최종 정산·지급.
- 알뜰소비플랫폼: 참여 관리, 공개 데이터, 전단 게시, 연동 현황·이력.
- 홈페이지 관리: 게시판·게시물, 배너·팝업, 메뉴·콘텐츠, 회원가입 안내.
- 공통: 공지사항, 종합 통계, 협회 설정.

### mart

- 회원사 관리: 회원사 정보, 점포 운영 관리, 관리자 계정 관리.
- 사업 참여 관리: 농할 참여, 알뜰소비 참여, 향후 사업.
- 농할 운영: 행사상품 등록, 집행 실적, 이상 감지.
- 농할 정산: 정산 청구, 불인정·재심사, 최종 정산·지급.
- 알뜰소비플랫폼: 공개 데이터, 전단 게시, 소비자 노출 미리보기, 연동 현황·이력.
- 공통: 공지사항.

마트 데모 계정은 대표 관리자이므로 자기 회원사의 세 점포를 조회한다. '지역 상생사업 (확장 예시)'를 선택하면 자기 참여점포가 없어 운영 메뉴와 참여점포는 없고, 사업 참여 안내/회원사 공통 메뉴는 유지된다.

### 지회 모델 (로그인 계정 없음)

자기 지회 회원사/지회정보/회비, 주차별 계획/행사상품/집행/정산/불인정/최종정산, 알뜰소비 조회와 공지를 정의했다. 위임 예산 액션은 아직 구현하지 않아 기본 거부한다. synthetic 지회 계정으로 범위/메뉴를 자동검증했다.

| StoreParticipation | businessId × storeId, 사업별 점포 참여상태 |
| Account | 조직, Role, 계정상태, 회원사, 전체 조직/전체 회원사/지정 점포 접근범위 |
| Role | 시스템/AT/협회/지회/마트 대표·부·일반; 데이터 범위와 family |
| Program | 공통 ID/표시명/그룹/적용 범위/목적/사용여부, 사업 조회 Context 적용 여부(contextScope) |
| BusinessProgram | 사업별 업무 프로그램 연결 |
| Permission / OrganizationPermissionOverride | Role별 조회/액션, 조직 예외 구조, Role별 메뉴명 변경 |

Mock seed는 한국마트협회/경기·강원지회/한빛유통/본점·강서점·마곡점과 별도 지역유통연합/새봄유통/점포를 포함한다. 별도 조직은 데이터 범위 누수와 확장성을 확인하는 가상 예시다. 접근 판정은 기관명이나 POS명 비교 없이 ID·관계·Role scope를 사용한다.

사업 3개는 `2026 농축산물 할인지원`(진행), `알뜰소비플랫폼`(진행), `지역 상생사업 (확장 예시)`(준비)다. admin은 모두, at/assn은 연결된 두 사업, mart는 신청 안내가 열린 미참여 사업까지 선택 가능하다. 미참여 사업 선택이 타 조직 데이터 접근을 허용하지 않는다.

메뉴와 직접 경로 접근 모두 같은 `canAccessProgram`을 사용한다. 업무 프로그램은 `사업-프로그램 매핑 ∩ Role 권한 ∩ 계정 범위/점포 참여`를 적용한다. 플랫폼/조직 공통 프로그램은 해당 공통 범위를 사용하며 특정 사업 미참여 때문에 로그인/회원사/신청 경로를 잃지 않는다.

## 공통 상태 사전

`src/types/status.ts`에서 사업, 계정, 사업참여, 행사 주차, 행사상품 등록, POS 연동, 정산, 불인정·재심사, 지급 상태를 PRD 표시명과 코드로 공통화했다. `StatusCode<영역>` 타입으로 다른 객체의 상태 혼용을 방지한다.

각 업무의 상태전이 엔진/액션/원장/스냅샷은 이번 범위에 포함하지 않는다. 계정의 '영구삭제 가능' 표시는 PRD 상태 사전에 포함했으나 실제 삭제 가능성 판단이나 삭제 액션은 아직 없다.

## 준비 화면과 다음 단계

실제 구현 화면은 로그인, 역할별 기반 홈, 참여점포 검색/상세, 조직 계층 조회, 시스템 프로그램 목록이다. Sidebar의 나머지 메뉴는 공통 준비 화면으로 연결되며 CRUD/승인/예산/파일 업로드/정산/지급/전단 처리는 구현되지 않았다.

다음 단계는 전체 구현계획의 순서를 따라 다음 기능을 연결한다.

1. 조직·계정·Role 권한·사업-프로그램의 편집/검증/감사와 실제 액션 권한.
2. 회원사 가입/계정 승인, 회원사·점포 운영정보, 사업 참여 심사/효력, 회비/초기이관.
3. POS Capability/스키마/매핑/점포 연결검증과 Excel 공통 인터페이스.
4. AT 주차계획→협회 예산/지회 위임→상품등록의 첫 업무 흐름.

## PRD 관련 결정 및 미정 사항

- PRD와 충돌하도록 기존 테스트 화면을 보존하지 않았다. 기반 단계라는 이번 지시로 상세 업무를 준비 화면으로 한정했다.
- mart는 대표 관리자이며 부/일반 관리자 계정과 지회 로그인 추가 여부는 후속 범위다. Role 모델과 지정점포 접근 구조는 준비되어 있다.
- 사업 선택은 해당 사업의 업무 메뉴만 표시하는 방식으로 결정했다. PRD의 농할/알뜰소비 IA는 각각 사업 선택으로 접근한다. 조직 공통 메뉴/신청 메뉴는 유지한다.
- 시스템 관리자의 전역 프로그램 조회는 프로그램 목록을 통해 제공한다. Sidebar에는 PRD 시스템 운영 IA를 기본으로 유지한다.
- 후속 사용자 지시에 따라 협회/마트는 농할 운영과 농할 정산, AT는 농할 운영과 정산 관리로 그룹을 분리했다. 기존 프로그램 ID/Route/Role 권한/사업 연결은 유지한다. 지회는 기존 메뉴 그룹을 유지한다.
- 시스템 관리자 상단 선택은 '업무 조회 사업'이다. 조직/계정/권한/프로그램/POS 마스터/표준 스키마/공통코드 등 전역 화면은 사업 선택을 접근 조건이나 데이터 필터로 사용하지 않는다. 전역 화면에서 사업을 바꿔도 화면과 데이터 범위를 유지하며, 사업 변경만으로 화면을 재마운트하지 않는다.
- '참여 조직·역할', '사업-프로그램 매핑'은 플랫폼 관리 메뉴이지만 사업 연결을 조회하므로 명시적 사업 Context를 적용한다. 농할/정산/공개 업무와 홈의 사업 관련 집계도 선택 사업을 적용한다.
- 프로그램 마스터 목록은 모든 사업에서 동일하다. 선택 사업에 연결되지 않은 업무는 목록에서 유지하되 해당 업무로 이동하는 링크를 제공하지 않는다.
- 이번 단계의 프로그램 권한은 조회만 부여했다. 수정·배분·판정·지급 등 특수 액션은 아직 없으며 후속 구현 시 Role/조직 예외/업무상태를 함께 검증해야 한다.
- 중지된 점포의 사업 이력은 조회 가능하도록 모델을 준비했다. 신규 업무 액션 차단은 상세 업무 단계에서 구현한다. 현재 seed에는 참여중/참여예정/미참여 사례가 있다.
- AT API/금융/POS 규격, 계좌 귀속, 부관리자 상한, 정산 차수 묶음 등 기존 PRD의 미정 정책은 이번 단계에서 확정하지 않았다.
- 농할 주차·정산차수·원장 등 상세 도메인 모델은 아직 생성하지 않았으며 PRD의 분리 원칙에 따라 다음 단계에서 추가한다.

## 검증 결과

- `npm run dev -- --host 127.0.0.1 --port 5173 --strictPort`: 기동 및 HTTP 200 확인 후 종료.
- `npm run build`: TypeScript 및 일반 Vite 빌드 통과.
- `npm run build:single`: 빌드 및 단일 HTML 정적 검사 통과. `dist/adms-demo.html` 1개, 321,614 bytes.
- `npm run lint`: 경고/오류 없이 통과.
- `node scripts/check-foundation.mjs`: 참조 무결성/조직 순환/로그인/세션/사업·Role·점포 범위/지회·일반관리자 모델 검증 통과. 개발용 Node 24의 TypeScript stripping을 사용한다.
- Windows Edge의 `file://` 실행, network offline + localStorage 허용/차단 각각: 네 계정 로그인, 잘못된 ID/PW, 모든 Sidebar 경로, 보호 경로 직접 접근 차단, 사업전환, 검색/필터/상세/Escape, 새로고침, 로그아웃/뒤로가기/재로그인 통과.
- 손상된 저장 세션의 로그인 복구, 390px 모바일 메뉴 및 가로 넘침 검사 통과.
- 후속 IA 검증: 협회/마트/AT의 운영·정산 그룹과 기존 Route 연결, 세 사업 전환 시 전역 마스터 범위/프로그램 목록 불변, 사업 연결 화면의 조회 Context 변경을 localStorage 허용·차단 상태 모두에서 확인했다.
- 브라우저 테스트에서 외부 JS/CSS/CDN/네트워크 리소스 요청 0, JavaScript 오류 0.
- Chrome 실브라우저 검증은 별도로 수행하지 않았다. 이번 직접 실행 검증 브라우저는 Windows Edge다.
- React Router의 호출되지 않는 비정적 라이브러리 로더가 최종 번들에 남아 정적 검사에서 안내된다. 실제 검사한 모든 경로는 추가 파일/네트워크를 요청하지 않았다. 이후 기능 추가 시 이 검증을 유지한다.
