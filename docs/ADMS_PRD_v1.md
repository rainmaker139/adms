# 1. 문서 목적 및 기준

| **Source of Truth** 본 PRD가 현재 설계의 기준이다. 기존 목업은 참고/수정 대상이며, 기존 구현 구조 때문에 본 PRD의 업무 구조를 축소하거나 왜곡하지 않는다. |
|-----------------------------------------------------------------------------------------------------------------------------------------------------------|

## 1.1 문서 목적

- 한국마트협회 중심으로 논의한 회원·조직·농할·알뜰소비플랫폼 업무를 하나의 제품 요구사항으로 통합한다.

- IA 에이전트가 기존 목업을 재구성할 때 화면별 목적·데이터 범위·상태·액션을 오해하지 않도록 기준을 제공한다.

- Codex 등 구현 에이전트가 동일한 도메인 모델과 권한/상태를 공유하도록 한다.

- 외부기관/API/POS의 미확정 상세는 일반적이고 확장 가능한 인터페이스로 정의하고, 실제 협의 후 교체 가능하게 한다.

# 2. 제품 개요와 설계 원칙

## 2.1 제품 한 줄 정의

| **제품 정의** 여러 POS의 데이터를 표준화하고, 조직·사업·권한을 기반으로 회원관리부터 농할 계획·집행·정산·지급, 외부 공개까지 연결하는 멀티조직 통합 운영 플랫폼. |
|------------------------------------------------------------------------------------------------------------------------------------------------------------------|

## 2.2 핵심 목표

- 협회와 마트의 반복 수작업을 줄이고 현재 Excel 중심 업무를 단계적으로 시스템화한다.

- 연동 불가 POS, 부분 연동 POS, 고도 연동 POS가 같은 업무 프로세스 안에서 공존하도록 한다.

- POS를 플랫폼 규격에 맞춰 과도하게 개조시키기보다 HUB가 POS별 차이를 흡수한다.

- 농할의 사후 불인정 확인을 넘어 행사 전 검증·집행 중 이상 감지로 정산 위험을 앞단에서 줄인다.

- 전체 상품가격 공개가 아니라 농할·현재 행사상품 등 마트가 공개 가능한 데이터만 선별하여 알뜰소비플랫폼에 제공한다.

- 한국마트협회 전용 시스템으로 고정하지 않고 다른 협회·대형마트·공공사업까지 공통 기능을 재사용한다.

## 2.3 설계 원칙

| **원칙**                       | **설명**                                                                                            |
|--------------------------------|-----------------------------------------------------------------------------------------------------|
| 업무 효율 우선                 | 시스템화 자체가 목적이 아니다. 요청→승인 등 불필요한 워크플로우가 오히려 일을 늘리면 만들지 않는다. |
| 조직과 사업 분리               | 조직은 지속되는 마스터, 사업은 기간·정책을 가진 컨텍스트. 동일 조직이 여러 사업에 참여 가능.        |
| 회원사와 점포 분리             | 회원사는 가입/계약/조직 단위, 점포는 POS·거래·행사·사업 참여의 실제 운영 단위.                      |
| Capability 기반 POS            | 1/2/3 등급 대신 기능별 지원 여부를 옵션화하고 화면/프로세스가 이를 참조.                            |
| Excel을 정식 인터페이스로 인정 | 임시 우회가 아니라 API/DB/파일과 동등한 입력·출력 경로 중 하나로 설계.                              |
| 원본 스냅샷 보존               | 최초 청구, AT 결과, 재심사, 최종 정산은 서로 덮어쓰지 않고 단계별 원본/이력을 보존.                 |
| Soft Delete 기본               | 업무·감사 이력이 있는 계정/조직은 논리삭제. 물리삭제는 시스템관리자 제한 기능.                      |
| 공통화 + 조직별 분리           | 공통 프로그램을 재사용하되 홈·공지·브랜딩·사용사업은 조직별 분리 가능.                              |

# 3. 핵심 도메인 모델

## 3.1 핵심 객체

| **객체**                               | **정의**                                                     | **핵심 관계**                           |
|----------------------------------------|--------------------------------------------------------------|-----------------------------------------|
| 사업(Business)                         | 기간·정책·주관/운영기관·참여정책을 가진 최상위 업무 컨텍스트 | 조직과 N:M                              |
| 조직(Organization)                     | AT, 협회, 기업, 지회 등 플랫폼을 사용하는 조직 마스터        | Parent-Child 트리                       |
| 회원사(Member Company)                 | 협회 가입/계약의 상위 단위. 사업자정보와 대표관리자를 가짐   | 1:N 점포, 1:N 관리자                    |
| 점포(Store)                            | 실제 영업·POS·거래·행사·사업참여의 운영 단위                 | POS 1개(현재) + 사업별 참여 속성        |
| 관리자 계정(Account)                   | 로그인 사용자                                                | 소속 조직 + Role + 접근 점포 범위       |
| Role/권한                              | 메뉴 및 액션 권한                                            | 계정에 부여, 소속조직 범위와 결합       |
| 행사 주차(Event Week)                  | 목~수 1주 단위 농할 운영 회차                                | 기간 중복 불가, POS 행사 매칭의 날짜 키 |
| 정산 차수(Settlement Batch)            | 여러 행사 주차의 정산을 묶을 수 있는 정산 처리 단위          | 1:N 행사 주차 지원                      |
| 대표상품(Standard/Representative Item) | AT/사업계획상의 표준 행사 품목                               | 1:N 실제 판매상품                       |
| 판매상품(Store Product)                | 점포/POS에서 실제 판매되는 SKU/상품                          | 대표상품에 매핑                         |
| 예산원장                               | 총예산/배정/예비비/회수/정산환원 변동 기록                   | 모든 증감 로그                          |
| 최초 정산청구                          | 협회가 최초 제출한 불변 스냅샷                               | 이후 불인정/재심사와 분리               |
| 불인정건                               | AT/정산 검토에서 인정되지 않은 거래/금액                     | 건별 소명·재심사 상태                   |
| 공개데이터                             | 알뜰소비플랫폼에 제공 가능한 농할/행사 상품                  | 연동형 또는 게시형                      |

| **중요 보완** 공식 사업은 매주 목~수로 행사하지만 원가정산은 연중 여러 차례(1~2개월 단위) 진행된다. 따라서 UI에서 “회차/주차”를 사용하더라도 내부 모델은 행사 주차와 정산 차수를 분리하고, 정산 차수가 하나 이상의 행사 주차를 포함할 수 있게 한다. |
|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|

> **공식자료 근거:** 행사주기 목~수: 사업설명회 p.6, p.16. 원가정산 연중 8~9회/1~2개월 단위: p.29.

# 7. 시스템 관리자 요구사항

## 7.1 홈

- 전체 조직/사업/점포 수 요약

- POS 연동 정상/설정중/오류

- 자동작업/외부연동 헬스체크

- 최근 중요 감사 이벤트

- 처리 필요 운영 이슈

## 7.2 조직 관리

| **핵심** 한국마트협회 전용 하드코딩 금지. 조직은 동적 Parent-Child 트리이며 사업과 독립된 마스터다. |
|-----------------------------------------------------------------------------------------------------|

| **항목**    | **요구사항**                                                                 |
|-------------|------------------------------------------------------------------------------|
| 조직유형    | 공공기관/협회/기업/지회/지역본부/회원사/점포/기타 등 확장 가능               |
| 조직 트리   | 등록·수정·이동·비활성화. 기본 권장 계층은 운영조직→지회/지역조직→회원사→점포 |
| 사업 연결   | 사업과 N:M 매핑. 사업 내 역할(관리감독/운영/참여/실행점포)을 별도 지정       |
| 조직별 설정 | 홈 구성, 공지 범위, 브랜딩, 사용 메뉴, 홈페이지 사용 여부 등                 |
| 삭제        | 참조 이력 존재 시 논리삭제/비활성. 물리삭제 제한                             |

## 7.3 관리자 계정 관리

- 시스템/AT/협회/지회 운영계정 생성·수정·비활성·잠금해제

- 소속 조직과 Role 지정

- 마트 계정은 일상적으로 마트 대표가 관리하되 시스템관리자는 복구/감사 목적 접근 가능

- 계정별 최근접속·상태·권한·소속 표시

## 7.4 권한 관리

| **UI 패턴** 좌측 Role 목록 + 우측 현재 IA의 메뉴/액션 권한 Matrix. 시스템 관리자 Role은 보호된 마스터 Role로 전체 메뉴/전체 데이터 접근. |
|------------------------------------------------------------------------------------------------------------------------------------------|

- Role 생성·수정·비활성화

- 메뉴 접근권한 + 조회/등록/수정/삭제 기본 액션

- 예산 배분/예비비 투입/불인정 판정/재심사 승인/지급 실행 등 업무 특수 액션은 상세권한으로 확장

- Role 기본권한 + 개별 조직 예외권한 지원

- Role 변경은 해당 Role 사용 계정에 즉시 반영

- 변경 전후 감사로그 저장

## 7.8 자동 작업 현황

- 설정 화면이 아니라 헬스체크 중심

- 작업명/업무영역/주기/상태/마지막 정상실행/마지막 결과/다음 예정/최근 처리건수/오류요약

- 상세 로그와 안전한 재실행만 제공

- Cron/스케줄 정의 수정은 개발·인프라 영역으로 남김

## 7.9 알림 관리

- 새 알림 유형 자체는 개발자가 시스템에 등록

- 운영자는 알림 사용 On/Off, 대상, 채널, 발송시점, 반복, 임계값을 조정

- 수치 기반 임계값은 코드 수정 없이 변경 가능

- 예: 예산 소진 임박 80%, 상품등록 D-1, 무실적 N시간, 연동지연 N분

## 7.10 감사/변경 이력

- 시스템관리자 전용

- 기간/사업/조직/사용자/메뉴/작업유형/대상/성공실패 필터

- 변경 전후 값·처리자·일시·사유·관련파일/연계ID 보존

- 예산/예비비/POS/회원핵심정보/계좌/권한/조직/사업/정산/Excel/재처리 등 주요 이벤트 기록

- Excel 등 자료 추출

# 8. 협회 관리자 요구사항

## 8.1 홈

- 공지사항 최근 5건 및 관리

- 협회 운영 KPI: 회원사/가입심사/회비 등

- 농할 운영: 금주 예산·집행률·선정/진행점포·처리필요사항

- 카드/수치 클릭 시 관련 상세 화면으로 이동

## 8.2 공지사항

- 협회가 시스템 사용자에게 게시, 마트/지회 등은 조회

- 중요 공지 고정/대상범위 지정 가능

- 조직별 공지 분리

## 8.3 회원·조직 관리

| **메뉴**       | **핵심 요구사항**                                                                                                                                    |
|----------------|------------------------------------------------------------------------------------------------------------------------------------------------------|
| 가입/참여 심사 | 홈페이지 회원사 가입 신청 + 농할 등 사업 참여 신청을 구분해 심사                                                                                     |
| 회원사 관리    | 회원사 공식정보, 점포, 참여사업, 회비/정산계좌 상태 확인                                                                                             |
| 핵심정보 수정  | 법인명/사업자번호/대표자/대표자 연락처/사업자등록증/사용 POS/소속지회는 협회 관리자만 수정. 물리적 증빙 확인 후 반영, 별도 복잡한 승인 Workflow 없음 |
| 지회 관리      | 지회 등록/수정/비활성, 소속 회원사 조회. 회원사 지회 변경은 협회 관리자 직접처리 + 이력                                                              |
| 회비·수납      | 월 납부율, 미납/연체, 계좌 입금 자동매칭, 미분류 입금, 기타입금 분류/메모, 초기이관, 향후 CMS 자동이체                                               |

## 8.4 회비 입금 자동매칭

- 법인명/대표자명/상호/과거 매칭이력/금액 등으로 후보 자동 추론

- 자동매칭 결과는 관리자가 수정 가능

- 미매칭 입금은 회원사를 수동 지정

- 회비 외 가입비/기부금/사업분담금/기타 등 유형 지정 및 메모

- 기초이관 기록과 실제 은행거래를 출처값으로 구분

## 8.5 농할 \> 예산 관리

- 연간 총예산 + 추경/조정

- 가용예산/배정예산/집행예산/정산보류액/정산완료액 구분

- 회차 시작 기본 예비비 5%

- 예산 조정은 원장 방식: 유형/마트/증감액/전후잔액/사유/처리자/시각

- 계획 미확정 점포는 배정예산 0원 + 해당 금액 예비비 자동 회수

- 지회 위임형이면 지회 배정예산 = 소속점포 배정 + 지회 예비비

> **공식자료 근거:** 초기 배정 이후 실적·모니터링에 따른 차등배정, 집행률 저조 시 회수 가능: 사업설명회 p.9.

## 8.6 농할 \> 주차별 계획

- AT가 등록/Excel 업로드한 원천 계획을 협회가 수신·확인

- 행사기간은 중복 불가, 동일 주차 1개만 등록

- 협회 운영값: 계획명, 완료기한(D-2 설정 시 D-1 00:00 마감), 총 회차예산, 배분방식, 예비비율, 지회/점포 배정

- 정부 할인율·개인한도·대표상품 등 AT 원천값과 협회 운영값 분리 저장

- 협회 직접 점포 배분 또는 지회 배분, 균등/가중(Excel) 지원

> **공식자료 근거:** 전 채널 행사주차는 목~수 1주 단위, 지정품목 약 1주 전 공지: 사업설명회 p.6, p.19.

## 8.7 농할 \> 행사상품 등록현황

- 현재 미시작/다가오는 회차 기본선택, 이전 회차 조회

- 상단: 대상 점포, 등록/확정 수, 마감시각

- 탭: 미완료 / 확정완료 / 전체

- 대표상품별 실제 판매상품 매핑 상태, 사진 등록, 예외확정 여부 확인

- 한 대표상품은 기본 1개 판매상품 UX를 사용하되 데이터 구조는 1:N 허용

- 미완료 점포에 수동 알림 발송

- 예외확정 점포/항목을 별도 식별

## 8.8 농할 \> 집행 실적

- 진행 중 행사 주차 기본 선택, 이전 회차 조회

- 상단: 이번 주 집행예산/전체 소진율/진행 점포 수÷전체/현재 예비비

- 탭: 전체/소진/소진임박/실적없음/진행중

- 리스트: 점포명/지회/상태/배정/집행/잔여/소진율/마지막 집계

- 점포→품목→거래 상세 Drill-down

- 점포별 예산 투입/회수/예비비 이력

- 특정 요일 이전 고소진율 등은 알림으로 표시

## 8.9 POS 예산 반영 전략

| **유형**            | **동작**                                                                                |
|---------------------|-----------------------------------------------------------------------------------------|
| 행사 생성/쓰기 가능 | 협회/지회 계획 확정 시 POS에 상품 없는 베이스 행사 자동생성 + 예산/할인율/개인한도 반영 |
| 행사 조회/쓰기 가능 | 동일 행사기간의 POS 농할 행사 생성 여부를 배치 확인 → 발견 즉시 배정예산 반영           |
| 쓰기 불가           | 시스템이 확정 예산을 수치로 전달, 점포가 POS에 수동설정                                 |

| **POS 행사 매칭키** 농할은 한 주에 하나의 행사만 등록되고 기간 중복이 없다는 업무 규칙을 전제로, 외부 POS 매칭은 점포 + 행사 시작일 + 종료일을 사용한다. POS에 별도 공통 매핑키 추가를 요구하지 않는다. |
|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|

## 8.10 농할 \> 이상 감지

- 상품명/판매가 변경, 일정시간 이후 무실적, KAMIS 대비 이상가격, 예산 소진 후 할인 지속

- 기간외 거래, 개인한도 초과, 중복거래 의심, 지정품목 외 판매 등 확장

- 마트/관리자 정보까지 보여 즉시 연락/조치 가능

- 이상 감지는 협회 내부 운영·사전예방 도구이며 AT 화면에는 직접 노출하지 않음

> **공식자료 근거:** KAMIS 가격 비교 및 행사기준 준수 모니터링: p.7. 기간외/한도초과/중복/품목 불인정 사례: p.43~46. 평균판매가/대량판매 이상 관리: p.48.

## 8.11 농할 \> 정산 청구

- 상단: 청구대상 점포 수/청구예정금액/회차 상태

- 마트 리스트: 점포/지회/사업자번호/품목수/배정/집행/청구/매출건수/정산계좌

- 점포→품목→거래 상세

- 청구확정 시 최초 청구 스냅샷 생성, 이후 수정 금지

- AT 전송과 정산서 Excel 다운로드를 모두 제공

- AT 결과는 자동수신 또는 Excel 업로드를 모두 지원

> **공식자료 근거:** 정산자료는 POS 매출데이터 기반이며 회원ID·품목명·상품명·단가·행사기간·지원금·결제내역 등을 검토: p.27~28.

## 8.12 농할 \> 불인정·재심사

- 주차/정산차수 선택 및 상태별 조회

- 상단: 전체 불인정 건수/대상점포/불인정금액/재심사요청/정산성공/최종반려

- 불인정 사유 Top + POS별 건수/금액/불인정률

- 기본 마트별 그룹 보기 + 건별 보기 전환

- AT 정산결과 Excel 업로드 → 표준 불인정건 생성 또는 시스템 직접 판정 수신

- 마트 이의신청 → 협회 검토 → AT 재심사 → 최종승인/최종반려

- 모든 단계 버전/이력 보존

## 8.13 농할 \> 최종 정산·지급

- 최초청구/최종인정/최종불인정/인정률/예산환원 결과

- 재심사 중 금액은 정산보류액으로 유지, 최종 불인정 확정 시 가용예산으로 환원

- 정부 지급 대기 → 협회 입금 확인 → 점포 지급준비 → 지급 → 완료

- 1단계: 은행 일괄이체용 Excel/CSV 자동생성 + 지급결과 반영

- 향후: 협회 법인계좌 거래 감지 → 회차 후보 자동매칭 → 관리자 확인 → 계좌 검증 → 승인 후 API 이체

- 돈이 들어왔다고 즉시 자동송금하지 않고 관리자 지급 승인 필수

- 지급 실패 점포만 재처리, 중복송금 방지 지급ID

> **공식자료 근거:** 최종 정산 후 e나라도움 교부 절차를 거쳐 유통사로 지급: p.30, p.35~36.

## 8.14 알뜰소비플랫폼

- 전체 상품 가격 공개가 아닌 농할 + 현재 전단/행사 상품만 선별 제공

- 참여관리: 참여 점포 수, 공개품목 수(농할/행사), 지회/지역 필터

- 연동형: POS에서 현재 유효한 농할/행사 상품을 주기 전송

- 게시형: 전단 이미지 업로드 → 이미지 프로세싱/OCR → 상품 추출 → 마트 확인 → 게시기간 설정 → 원본 전단 이미지 + 구조화 데이터 제공

- 혼합형 지원 가능

- 최종 성공 연동시점/오류/재전송/이력 관리

## 8.15 종합 통계

- 회원: 전체/신규/지회/지역/POS/회비 납부율

- 농할: 예산/집행/소진율/품목/마트/지회/불인정/예비비

- 정산·지급: 청구/인정/불인정/재심사/지급

- 알뜰소비: 참여율/공유상품/연동형·게시형/성공률

- 공통 필터: 기간/사업/지회/지역/POS/회원사

## 8.16 홈페이지 관리

- 게시판/게시물, 배너, 팝업, 메뉴/콘텐츠, 회원가입 안내

- 협회 홈페이지의 회원사 가입 신청이 통합관리시스템 가입심사로 자동 연결

- 홈페이지 콘텐츠와 시스템 공지는 목적을 구분하되 동일 CMS 기반 활용 가능

# 10. 마트 관리자 요구사항

## 10.1 가입/계정 시작 흐름

- 협회 홈페이지에서 회원사 가입 신청

- 협회 승인 → 회원사 코드 생성 + 대표 관리자 아이디/임시비밀번호를 대표자 전화번호로 발급

- 일반 관리자는 통합시스템에서 회원사 검색/선택 후 가입 신청

- 대표 관리자 또는 제한된 수의 부관리자가 승인

- 대표 관리자는 전체 점포, 일반 관리자는 지정 점포만 접근 가능

## 10.2 홈

- 공지사항

- 협회 운영: 회비 납부, 관리자 가입승인 대기 등

- 농할: 금주 집행/차주 상품등록/불인정·재심사 등 “지금 처리할 일” 우선

- 권한/참여사업에 따라 카드 동적 노출

## 10.3 회원사 정보

| **구분**        | **마트 수정**                                      | **협회 수정**                                       |
|-----------------|----------------------------------------------------|-----------------------------------------------------|
| 공식 사업자정보 | 조회만                                             | 법인명/사업자번호/대표자/대표자 연락처/사업자등록증 |
| 운영정보        | 상호/대표전화/일반연락처/이메일/담당자/운영주소 등 | 필요시                                              |
| 사용 POS        | 조회만                                             | 협회 관리자만 + 강한 재확인 + 연동 재검증           |
| 소속 지회       | 조회만                                             | 협회 관리자만                                       |

## 10.4 점포 운영 관리

- 단일 점포도 기본 1개 점포를 가지며 추가 점포 등록으로 다점포 확장

- 점포명(상호, 법인명과 분리), 주소, 전화번호

- 기본 영업시간 + 반복 예외 + 특정일 예외/임시휴무

- 배송 여부, 전화주문/픽업 여부 등 속성

- 사용 POS/연동상태는 조회만

- 운영정보는 알뜰소비플랫폼 공개 점포정보로 재사용

## 10.5 관리자 계정 관리

- 가입승인/반려, 부관리자 지정/해제, 점포 접근권한, 정지/복구, 삭제(비활성)

- 삭제는 Soft Delete. 과거 업무/감사 이력 유지

- 대표 관리자 계정은 보호, 중요 변경은 별도 제한

- 비활성 계정 보기 필터

## 10.6 사업 참여 관리

- 회원사 기준으로 사업 신청 가능, 실제 참여 On/Off는 점포 단위

- 사업별 탭: 설명/조건/기간/상태/필수입력/첨부/신청이력

- 미참여 사업의 운영메뉴는 숨기고 사업 참여 관리만 노출

- 알뜰소비플랫폼은 자율중지, 농할은 진행 회차/정산 의무 종료 후 중지효력

- 회원사 전체 철회는 이 메뉴에서 처리

## 10.7 농할 \> 행사상품 등록

| **POS 유형** | **마트 동작**                                                     |
|--------------|-------------------------------------------------------------------|
| 완전연동     | 미리 생성된 행사/POS 상품 수집 → AI 가매핑 확인/수정 → 확정       |
| 부분연동     | POS에 농할 행사 설정 → 시스템 수집 대기 → 가매핑 확인/수정 → 확정 |
| 비연동       | 대표상품별 판매상품 직접입력 또는 지정 Excel 업로드 → 확인/확정   |

- 대표상품 1개에 판매상품 여러 개 매핑 가능(기본 UX는 1개, “판매상품 추가”로 확장)

- 대표상품별 행사관리 사진 업로드, 행사 전체 추가 첨부파일 지원

- 확정 시 매핑누락/상품명/필수품목/사진 등 검증

- 미충족 시 확정 차단 + 구체적 오류 안내

- 예외옵션: 행사 시작 전 상품명 변경 예정, 일부 품목 미진행 등. 예외 없이는 확정 불가

- D-day/마감시각 명확히 표시

- 예외확정 건은 행사 시작 시점 배치 재검증

## 10.8 농할 \> 집행 실적

- 조회 중심

- 회원사 소속 모든 점포를 합계+점포별로 조회

- 회차 선택, 배정/집행/잔여/소진율/마지막 집계

- 점포→품목→거래 상세

- 추가예산 요청 Workflow는 만들지 않음. 기존 물리적 소통 + 협회 자동알림 활용

## 10.9 농할 \> 이상 감지

- 연동 점포: 회차별 누적데이터를 지속 분석

- 비연동 점포: 결과보고 Excel을 일회성 분석. 최신 업로드 파일 기준으로 페이지 전체 갱신, 누적저장하지 않음

- 비연동에서 판단 가능한 상품명 상이/판매가 변동/KAMIS 이상가격 등만 검출

- 마트는 본인 점포 이상 상세/원천데이터 조회 중심

## 10.10 농할 \> 정산 청구

- 정산용 거래데이터 자동수집 가능 점포: 검증 통과 거래 자동 청구, 마트는 조회만

- 상품명/판매가 등 검증 실패 거래는 청구 제외 + 사유 표시

- 비연동: 결과보고 Excel 업로드 → 파싱/기본검증 → 미리보기 → 협회 상신

- 정산청구 Excel은 공식 제출 근거로 저장/보존(이상감지 일회성 Excel과 구분)

- 상신 전 재업로드 가능, 상신 후 최초 스냅샷 불변

- 화면은 협회가 해당 마트를 Drill-down한 상세와 동일 구조 재사용

## 10.11 농할 \> 불인정·재심사

- 협회와 같은 데이터 구조, 자기 회원사 점포만 조회

- 불인정 건별 코멘트 + 사진/거래명세표/문서 등 증빙 첨부 후 재심사 요청

- 동일 상품 + 동일 불인정 사유 건에 동일 소명/첨부 일괄 적용 제안

- 일괄 적용 전 대상건 목록/건수 표시, 일부 제외 가능

- 일괄 적용하더라도 각 불인정건은 개별 레코드로 유지하여 최종판정 분리 가능

## 10.12 농할 \> 최종 정산·지급

- 회차/정산차수별 최초청구/최종인정/최종불인정/지급상태 조회

- 회원사 합계 + 점포별 상세

- 지급일/지급금액/지급계좌/상태

- 금융 연동 완성 시 이체확인증/지급확인 문서 조회·다운로드

- 별도 지급요청 액션 없음. 오류 시 상태/사유 + 협회 문의

## 10.13 알뜰소비플랫폼

- 참여 신청/전체 철회는 공통 사업 참여 관리에서 처리

- 공개 데이터 관리: 농할/행사 상품 현재 공개상태 확인 및 허용 범위 내 On/Off

- 전단 게시: 이미지 업로드 → 이미지 처리/OCR → 상품후보 → 확인수정 → 게시기간 → 게시

- 소비자 노출 미리보기: 점포 운영정보 + 공개상품 + 전단을 앱/모바일 에뮬레이션으로 표시

- 현재 공개 화면(마지막 성공 전송)과 다음 반영 예정 화면 비교

- 연동 현황·이력: 마지막 성공/다음예정/성공·실패/오류/재전송 상태

# 11. AT 사용자 요구사항

## 11.1 홈

- 전체 참여점포

- 금주 집행금액/진행률

- 정산 대기/불인정/재심사 현황

- 누적 집행

- 최근 처리 필요 정산건

## 11.2 농할 \> 주차별 계획 관리

- AT가 공식 주차계획 직접등록 또는 공식 Excel 업로드

- 시스템이 행사기간/대표상품/할인율/개인한도 등 표준 데이터로 변환

- 협회는 이를 재작성하지 않고 확인/수신 후 예산운영

- 원본 Excel/등록이력 보존

## 11.3 농할 \> 운영 현황

- 협회의 참여점포/행사상품 준비/집행실적을 감독용 View

- 필요 시 점포/품목/거래 Drill-down

- 협회 내부 이상감지 메뉴는 AT에 제외

## 11.4 농할 \> 청구 내역 관리

- 협회 최초 청구 스냅샷 수신/조회

- 회차/협회/점포/품목/거래 상세

- 원본/정산 Excel 다운로드

- 향후 시스템 직접 검토와 Excel 검토를 동일 데이터 구조로 처리

## 11.5 농할 \> 불인정·재심사

- 현재 기본: 정산결과/불인정 Excel 업로드 → 시스템 파싱 → 건별 불인정 생성

- 향후 목표: AT 담당자가 거래/품목에서 직접 불인정 처리, 사유·금액 입력

- 마트 증빙/코멘트 + 협회 검토내용 확인

- 최종 승인/최종 반려를 시스템에서 직접 처리 가능

- Excel과 시스템 직접처리는 동일 상태/이력 모델 사용

## 11.6 농할 \> 최종 정산

- 최종 인정/불인정/정산 상태 조회

- AT는 최종금액 확정/정산공문 영역까지

- 협회→마트 실제 지급 실행은 AT 권한 아님

> **공식자료 근거:** 최종 정산 후 aT 정산공문, 유통사는 e나라도움 교부신청: 사업설명회 p.30.

## 11.7 알뜰소비플랫폼

- 협회가 보는 참여현황/공개데이터/전단/연동상태·이력을 동일 범위로 View

- 참여 On/Off, 공개설정, 전단수정, 재전송 등의 운영 액션 없음

- 소비자 노출 미리보기는 필수 AT 기능이 아님

# 12. POS/Data HUB

## 12.1 POS 마스터

- POS사/제품명/회사명/대표·책임자/실무담당/연락처/이메일/홈페이지/사용여부/비고

## 12.4 점포 POS 연동 관리

- POS 지정 ≠ 연동완료. 실제 점포 접속정보와 식별자 입력 필요

- POS 마스터의 연동 프로파일에 따라 동적 입력폼 생성

- 로컬형: 매장코드, 서버/DB Host/IP, Port, DB/Instance, Agent, 인증·허용정보 등

- 클라우드형: POS 매장/가맹점 코드, Tenant, API Key/Secret 등

- 민감값 마스킹/암호화, 권한관리

- 연결테스트 → 점포식별 → 샘플데이터 → 스키마검증 → Capability별 테스트 → 활성화

- POS/접속정보 변경 시 강한 경고 + 재검증 + 이력

# 15. 공통 알림·감사·보안·운영

## 15.1 알림

- 시스템 알림/문자/SMS/알림톡 등 채널은 설정 가능 구조

- 알림유형 On/Off, 수신 Role/조직범위, 발송시점, 반복, 임계값, 메시지템플릿

- 처리 필요 알림은 홈 카드와 연결

- 대표 예시: 상품등록 마감, 행사 시작 예외미해소, 고소진율, 무실적, POS 오류, 불인정/재심사, 회비미납, 지급완료

## 15.2 보안/개인정보

- 회원ID/전화번호/계좌 등 화면 기본 마스킹

- Secret/API Key/DB Password 암호화 저장 및 원문 재표시 금지

- Role+조직+사업+점포 범위의 서버측 권한검증

- 파일 접근권한 및 다운로드 로그

- 정산계좌 검증상태가 정상 아니면 지급대상 생성 차단

## 15.3 변경/원본 보존

- 최초 청구 스냅샷, AT 결과, 소명, 재심사, 최종정산은 각각 별도 이력

- 예산은 잔액 직접수정이 아니라 원장 증감방식

- 계정/조직/사업/POS 변경은 변경 전후 감사로그

- 업무 이력 있는 데이터는 Soft Delete 기본

## 17.1 대표 목업 장면

- 협회 홈: 금주 예산/집행률/진행점포 + 처리필요 카드

- 마트 홈: 금주 집행 + 차주 상품등록 D-1 + 불인정 5건

- 행사상품: 대표상품별 가매핑, 사진, 예외 옵션, 확정 검증 오류

- 집행실적: 다점포 리스트와 점포→품목→거래 Drill-down

- 불인정: 동일 상품+동일 사유 18건에 소명 일괄적용 확인

- 알뜰소비: 현재 공개 vs 다음 반영 예정 모바일 미리보기

- 시스템관리자: Role Matrix, 사업-프로그램 매핑, POS Capability/스키마, 점포연동 상태

# 19. AI 에이전트 구현 지침

| **기존 목업 처리 원칙** 기존 목업은 유지해야 할 기준안이 아니다. 본 PRD와 충돌하면 본 PRD를 우선하고, 기존 목업의 쓸 만한 시각/컴포넌트만 재사용한다. |
|-------------------------------------------------------------------------------------------------------------------------------------------------------|

- IA 에이전트는 역할별 좌측 메뉴를 본 PRD 기준으로 재구성한다.

- 동일 업무 객체는 역할마다 별도 데이터 모델을 만들지 않고 공통 데이터를 공유하며, 데이터 범위와 액션만 Role에 따라 다르게 표현한다.

- 마트/협회/AT 화면의 “같은 상세”는 컴포넌트 재사용을 우선한다.

- POS 연동수준을 1/2/3 같은 등급으로 임의 단순화하지 말고 Capability 조합을 사용한다.

- 비연동 Excel 경로를 제거하지 않는다. API가 있다고 가정하여 버튼/화면을 생략하지 않는다.

- AT 화면에 협회 내부 “이상 감지”를 노출하지 않는다.

- 사업/조직/회원사/점포를 혼동하지 않는다. 특히 회원사≠점포, 사업≠조직.

- “법인명”과 “점포 상호명”을 분리한다.

- “지회”를 표준 용어로 사용한다.

- 기존 예시 화면의 프로그램/권한 관리 패턴은 참고하되 디자인은 현재 관리자 UI 기조로 현대화한다.

- 목업은 네트워크가 없어도 시연 가능하도록 샘플데이터와 상태 전환을 포함한다.

# 부록 C. 1차 PRD 완료 기준

- 역할별 IA가 정의되어 있다.

- 농할 End-to-End(계획→집행→정산→지급)가 연결된다.

- 회원사/점포/계정/사업/조직 관계가 분리되어 있다.

- POS Capability와 점포연동이 전체 화면 분기의 근거가 된다.

- Excel/API/직접처리가 동일 업무상태로 수렴한다.

- 공통 상태값으로 목업이 일관되게 표현 가능하다.

- 미정 외부연동은 TBD이지만 대체경로와 상태는 정의되어 있다.

- AI 에이전트가 기존 목업을 PRD 기준으로 재구성할 수 있다.
