| 사업-프로그램 매핑 `/p/business-programs` | 선택 사업에서 사용할 사업 업무 프로그램을 체크·저장. 프로그램 상태와 Role 권한을 결합해 실제 메뉴 노출. |

사업 마스터의 연결 탭과 두 연결 전용 메뉴는 같은 편집 컴포넌트를 사용한다. 프로그램 관리와 사용·중지도 하나의 전역 데이터를 공유한다.

시연 순서: `admin / 1234` 로그인 → 조직 생성/수정 → 계정 상태 변경 → Role 생성/권한 저장 → 사업 생성/조직 연결 → 프로그램 등록/사업 연결 → 해당 Role 계정으로 재로그인 → 메뉴 노출 확인 → admin에서 프로그램 중지 → 대상 계정의 메뉴/직접 경로 접근 차단 확인.

## 3. Mock 데이터와 관계

초기 데이터는 조직 13개, 회원사 2개, 점포 4개, 계정 7개, Role 7개, 사업 4개, 프로그램 56개다. 로그인 화면에는 기존 4개 데모 계정을 유지한다. 추가 계정도 정상 상태라면 공통 데모 비밀번호 `1234`로 로그인할 수 있다.

- **Organization**: 부모 ID로 동적 계층을 구성. 사업을 이 Tree에 포함하지 않는다. 한국마트협회 → 경기지회 → 한빛유통(주) → 본점/강서점/마곡점, 강원지회 및 별도 지역유통연합 예시 포함. 휴면 조직도 제공한다.
- **MemberCompany / Store**: 각각 독립 ID와 조직 노드 참조를 가진다. Store는 companyId를 참조한다. 점포 간 POS 차이 등 기존 데이터는 유지한다.
- **Account → Organization + Role + storeAccess**: 마트 대표/부/일반 사례를 제공하고 정상·승인대기·정지·비활성을 섞었다.
- **Business ↔ BusinessOrganization ↔ Organization**: 사업 내 역할은 조직유형과 별도 필드다. 농축산물 할인지원, 알뜰소비, 준비 중 상생사업, 종료된 수산대전 사례를 제공한다.
- **Program ↔ BusinessProgram ↔ Business** 및 **Role ↔ Permission ↔ Program**: 플랫폼/조직 공통 프로그램은 사업 선택과 독립적이며, 사업 업무 프로그램은 사업 매핑을 거쳐 노출된다.
- **StoreParticipation**: 조직 연결과 참여 승인 상태를 분리한다. 신규 실행점포 연결 시 참여 초안만 생성하고 참여 승인으로 간주하지 않는다.
- **changes**: 저장 시 작업자, 시각, 객체 구분, 변경 전후를 기록한다. 감사 조회 화면은 이번 범위에서 구현하지 않았다.

`adms.demo.data.v2`에 전체 데모 상태를 저장하고 `adms.demo.session.v1`에는 세션 식별자만 저장한다. Role·조직·권한은 최신 마스터에서 다시 계산한다. 저장 차단·용량 초과 시 현재 React 메모리 상태를 유지한다. 저장 JSON/관계/계층이 손상되면 기본 데이터로 복구한다. 브라우저가 저장을 허용하지 않으면 새로고침 이후 변경은 유지되지 않는다.

## 4. 보호 및 적용 원칙

- 코드/로그인 ID 중복, 조직/메뉴 순환, 유효하지 않은 점포 소속을 검사한다.
- 기본 admin 계정, 플랫폼 운영 조직, 시스템 Role 및 핵심 관리 프로그램을 보호한다.
- 조직·계정·Role·프로그램은 물리삭제하지 않는다. 비활성화 후 복구할 수 있다.
- Role과 상위조직 비활성은 해당 계정 로그인에 반영된다.
- 프로그램 중지는 하위메뉴에도 적용된다. 직접 Hash 경로로 이동해도 접근 판정을 거친다.
- 종료·보관·일시중지 사업의 신청과 연결 편집은 제한하고 이전 연결 및 변경 이력을 보존한다. 사업 마스터 자체의 수정/상태 복구는 시스템 관리자가 수행할 수 있다.
- 모든 전역 마스터 목록은 상단 사업 선택으로 필터링되지 않는다. 사업 연결 화면과 홈의 사업 통계에서만 조회 Context를 사용한다.
- 농할 운영/농할 정산(AT는 정산 관리) 구분은 이전 사용자 합의를 유지한다.

## 5. 미구현 범위

시스템 관리자 메뉴 중 아래 16개는 기존 준비 화면을 유지한다.

- POS HUB 7개: POS 마스터, Capability, 데이터소스·인터페이스, 표준 스키마, 필드·코드 매핑, 점포 POS 연동, 연동 현황·이력.
- 외부 연동 4개: AT, 알뜰소비플랫폼, 금융, 기타 연동.
- 시스템 운영 5개: Excel 양식, 자동 작업 현황, 알림 관리, 공통코드, 감사·변경 이력.

농할·정산·회원 가입 등 타 Role 상세 업무와 신규 등록 프로그램의 상세 업무 화면도 준비 상태다. 신규 프로그램의 **등록/매핑/권한/메뉴 접근**은 동작하지만 업무 화면 구현을 자동 생성하지는 않는다.

PRD의 조직별 브랜딩/홈 설정, 조직 예외권한 편집 UI, 계정 물리삭제·복구 감사 상세는 후속 범위다. 조직 예외권한 모델과 접근 계산은 기존대로 유지했다.

## 6. PRD 해석 및 결정사항

구조 원칙과 충돌하는 변경은 없다. 다음은 데모 구현 시 명시한 제한/후속 판단사항이다.

1. 계정의 화면 상태는 사용자 예시의 ‘활성’에 해당하는 PRD 공통값 ‘정상’을 사용한다. 사업의 ‘중지’는 PRD의 ‘일시중지’를 사용한다.
2. 프로그램 적용범위와 기존 Role 데이터 범위의 변경은 이관 작업이 필요하므로 기존 레코드에서는 고정했다. 새로운 범위는 새 Role/프로그램으로 생성한다.
3. 다른 회원사로 점포를 옮기는 경우 계정·참여·거래 이관 정책이 필요해 이번 단계에서는 차단한다. 일반 조직의 부모 변경, 지회/회원사 단위 이동은 허용한다.
4. 대표 관리자 비활성 시 후임 대표 강제 지정 정책은 미정이다. 요청대로 명시적인 영향 경고 확인을 제공한다.
5. 프로그램 사용중지는 관련 사업/Role 및 하위메뉴에 영향을 주지만 기존 권한/매핑은 보존한다. 지원 Action을 제거하는 경우 해당 권한은 정리된다.
6. 전역 마스터의 변경 명령은 시스템 관리자 전용이다. 다른 Role의 플랫폼 조회 권한은 확장 모델로 표현할 수 있지만 전역 편집 권한은 부여할 수 없다.
7. 사업-조직 연결은 참여 승인 업무와 분리한다. 새 실행점포는 초안으로 시작하며, 본 단계에서 운영 승인을 자동 확정하지 않는다.
8. 계정/조직 활성화에 별도 기관 정책이나 실제 인증·금융·POS 규칙을 추가하지 않았다. 모든 계정 비밀번호 `1234`는 오직 공개 Mock 시연 규칙이다.
9. 회원사 조직 생성은 마스터 등록이다. PRD의 신규 가입 시 기본 점포 생성/가입 승인 흐름은 후속 회원 가입 화면에서 구현한다. 이번 화면에서는 회원사 하위 점포를 별도로 등록한다.

다음 단계는 회원사·점포/가입·사업 참여 업무를 실제 화면으로 구현하고, 조직 예외권한과 상태별 업무 Action 적용을 확장하는 것이다. POS HUB·농할·정산의 세부 구현은 전체 구현계획 순서를 따른다.

## 7. 검증

검증 명령:

```sh
npm run lint
node scripts/check-foundation.mjs
node scripts/check-admin.mjs
npm run build
npm run build:single
node scripts/smoke-offline.mjs <개발 PC Playwright index.mjs 절대경로>
node scripts/smoke-admin.mjs <개발 PC Playwright index.mjs 절대경로>
```

- TypeScript 및 두 빌드 통과. `build:single` 후 dist에 `adms-demo.html` 하나만 생성.
- 외부 script/style/image/font 참조와 별도 번들 import에 대한 정적 검사 통과.
- Windows Edge를 headless 실행하고 브라우저 네트워크를 offline으로 지정한 뒤 **file:// HTML 직접 실행** 검증.
- 네 기본 계정, 전체 기존 메뉴, 운영/정산 그룹, 사업 전환, 전역 마스터의 사업 독립성, 범위 가드, 검색/상세, 로그아웃·새로고침 회귀검증 통과.
- 실제 클릭으로 조직 생성/수정/이동/회원사·점포 생성, 계정 상태 변경·대표 경고, Role 생성·권한 저장, 사업 생성·조직 및 프로그램 매핑, 신규 Role 계정 로그인, 프로그램 중지/재활성, 직접 경로 거부, 종료 사업 편집 제한 확인.
- localStorage 허용 시 새로고침 후 변경 유지. 차단 상태에서도 같은 시연 기능 통과.
- 모델 검증에서 조직 순환/점포 이관/중복 범위/보호 권한/저장 JSON 및 계층 손상 복구 확인.
- 390px 모바일 메뉴 및 관리자 화면 가로 넘침 검사 통과. 주요 화면 스크린샷 확인.
- 브라우저 검증에서 외부 요청 **0건**, JavaScript 오류 **0건**. Chrome은 별도로 실행하지 않았으며 Edge에서 직접 검증했다.
- 검증 도구(Node/Playwright/Edge 자동화)는 개발 PC에서만 사용하며 HTML 실행에는 포함하거나 요구하지 않는다.
